## 重要架構決策（非顯然行為）

### 1. 互動報名開關 = `site_config.interactive_config`

`{ open: boolean }`。關閉時：
- dashboard task card 隱藏
- `/member/interactive` 顯示「尚未開放」banner、表單停用
- `/api/interactive` POST 拒收
- **但 admin（cookie `admin_role=admin`）仍可操作**（後台預覽用）

### 2. 互動作業仍 gated by 中簽

雖然中途實作過「報名後即可填」（commit a16a44f），但被 user reverted。目前邏輯：
- `/api/interactive/task` 要求 `group_status='won'` 或 `small_status='won'`
- 信內含 task 連結的是「批次寄中簽通知信」（`/admin/interactive` 上的按鈕）
- 邀請信（`lib/interactive-invite-email.ts`）只含互動報名按鈕，**不含**互動作業按鈕

### 3. PATCH gate 移除

`/api/admin/interactive` PATCH 不再驗證「中簽必有指定」。委託人實際工作流：

> 操作員選中簽後，過幾天才安排場次／組別／序號（且分配的場次未必是學員第一意願）

防呆移到 notify 端：
- `noWin` → skip（都沒中不寄）
- `won && !assigned_*` → skip（中簽但未指定，提示補後再寄）
- 訊息會分開計數，admin UI 看得到

### 4. 後台預覽測試學員（兩層機制）

**層 1：admin cookie bypass**
- `/api/interactive` GET/POST 與 `/api/member/me` 偵測 `admin_role` cookie
- admin 視為 `open=true`，回傳 `interactive_preview=true`
- 學員看不到（沒 cookie），admin 用任何學員 id+code 進 `/member/interactive` 可操作

**層 2：自動建立測試學員**
- `/admin/interactive` 頁首「🔧 預覽表單」按鈕
- 點擊：先 GET 讀目前狀態 → prompt 詢問 email（帶現值預設）→ POST → 開新分頁進表單
- email 預設 `preview@test.invalid`（不收信），可改為任何能收信的 email
- 用 `site_config.preview_test_student.id` 追蹤 row（不靠 email），所以 email 可任意換
- 自動匯出（cron + 手動 CSV）都用 `getPreviewRegistrationId()` 排除這筆

### 5. 三種寄信時機

| 信種 | 觸發 | 路徑 |
|---|---|---|
| 錄取通知信 | `/admin/lodgings`「批次寄錄取通知」 | `lib/approval-email.ts` |
| 互動報名邀請信 | `/admin/lodgings`「批次寄互動報名通知」 | `lib/interactive-invite-email.ts` |
| 中簽結果通知信 | `/admin/interactive`「批次寄中簽通知信」 | `lib/interactive-notify-email.ts` |
| 正式學員通知信 | `/admin/lodgings`「批次寄正式學員通知」 | `lib/formal-notification-email.ts` |

## 關鍵 gotcha

1. **預覽模式下送出資料是真的寫進 DB** — 提示 banner 已警告，但 admin 還是可能誤以為是 dry-run
2. **`PREVIEW_DEFAULT_EMAIL = 'preview@test.invalid'`** — 故意用 `.invalid` TLD，bounce 也沒事；admin 改成真 email 後測試信才會收到
3. **匯出查詢必須包 `getPreviewRegistrationId()` 才會排除** — 未來新增匯出端點時記得加
4. **`/admin/interactive` EditModal 描述**：寫了「可先編場次再標中簽」，現在反過來也可以（先標中簽再排），文字未細修但行為都通
5. **`互動報名通知信` ≠ `中簽結果通知信`** — 是兩封不同的信，admin 容易混淆。手冊第四節有解釋
6. **登入頁是 `/admin/login`** 不是 `/admin`，proxy.ts 會 redirect
